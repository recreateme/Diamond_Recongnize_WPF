# 钻石检测结果 —— 单图均匀度评分模块说明

> **实现位置（权威）**：`python_core/diamond_uniformity.py`（WPF 经 Bridge `IUniformityAnalyzer` 调用）。  
> **产品用法**：见 [应用功能与算法说明.md](应用功能与算法说明.md)「均匀度」两入口（独立页 + 检测页联动）。  
> **本文定位**：算法设计、指标含义与已知局限的标准说明（原为原型文档，现与 `python_core` 实现对齐）。  
> 理论来源：前期《钻石平整度》分析笔记（点模式分析 Point Pattern Analysis），结合本项目数据特点取舍改造。

---

## 1. 背景与目标

产品是圆形disc，理论上表面均匀镶嵌约6000颗钻石。整盘图像按 24×24 网格切分
成 5120×5120 的 tile，用 YOLOv8 + SAHI 做检测，再用一个五分类模型给每颗钻石
打标签（`棱边朝上` / `点朝上` / `面朝上` 三个朝向类别，`断钻` / `局部破损`
两个缺陷类别）。

质检环节想知道的问题是：**这一张（或未来这一盘）图里的钻石排布是不是均匀
的**——有没有大片漏排、局部扎堆这类工艺缺陷。这不是"数量够不够"的问题，
而是"空间分布规不规则"的问题，本质上是空间统计学里的**点模式分析（Point
Pattern Analysis）**：给一组点（钻石中心），判断它是"规则均匀"“完全随机”
还是"聚集"。

目标是给每种算法产出一个**连续的数值分数**（不做"均匀/不均匀"的二分类判
断）。业务部门后续会针对同一批分数反复人工标注"这张图我看着均不均匀"，再
根据大量标注样本给每个算法自动定一个分割阈值——所以这一版脚本的职责边界
很清楚：**只负责稳定、可比较地产出原始分数，不负责下判断**。

## 2. 核心设计决策与理由

这些决策是在需求讨论过程中逐条拍板的，记录下每条的理由和代价，方便以后回
头复核或者做二期升级时知道"为什么当初这么定"。

### 2.1 分析粒度：单图(tile)级别，不做整盘坐标合并

**决定**：本期均匀度计算只在单张 tile 内部进行，不把多张 tile 的检测结果
拼接成整盘统一坐标系。

**代价（已知局限，见第5节）**：圆盘边缘的 tile 可能只拍到圆盘的一小段弧形
区域，钻石可能只出现在图像的一个角落。凸包边界法（见2.3）能防止"图的大部
分根本不属于圆盘"被误判成"极度稀疏"，但换来的代价是：**凸包边界处如果真
的有漏检（本该有钻石但没检测到），这类边缘缺陷会被"隐形"排除在统计之
外**——因为凸包天然收缩到已检测点的范围，边界本身就是拿数据"框"出来的，
不是拿真实圆盘边界框出来的。

二期如果做了 tile → 整盘全局坐标的拼接，应该用真实圆盘圆心+半径重新跑一遍
这几个指标，很可能会额外发现一批当前方法漏判的边缘缺陷。

### 2.2 前置过滤规则

进入空间统计之前，检测结果按两条规则过滤：

1. **置信度过滤**：`det_conf >= conf_threshold`（默认 0.25）。不过滤的话，
   误检的"幽灵点"会人为制造局部聚集假象。
2. **类别过滤**：`defect_class` 只保留 `棱边朝上` / `点朝上` / `面朝上`
   三个朝向类别；`断钻` / `局部破损` 不参与空间位置统计（分类模型仍然会
   正常输出这两个类别，只是均匀度模块不用它们的位置信息）。

   这条规则背后的业务含义是：均匀度模块只关心"这个位置上有没有一颗（判定
   为完好朝向的）钻石"，缺陷率是另一个正交的、独立的指标，不应该混进均匀
   度的统计里。

### 2.3 有效分析区域：凸包（Convex Hull）

Voronoi / 最近邻 / 网格密度这几个方法都需要知道"分析区域的面积有多大"（分
母），如果直接用整张 5120×5120 图像的面积，边缘 tile 会被严重误判成"极度
稀疏"。

**决定**：用检测点（钻石中心）集合的凸包面积作为分母/边界。所有裁剪、密度
计算都以这个凸包为准，输出里带一个 `boundary_method: "convex_hull"` 字段
明确标注这个假设。

局限已经在 2.1 提到：凸包边界对"贴边漏检"是盲的。这是"单图分析、不做整盘
合并"这个架构选择的直接代价，不是凸包方法本身的缺陷——如果有整盘坐标 +
真实圆盘边界，应该优先用真实边界而不是凸包。

### 2.4 尺寸差异归一化

钻石表观大小可能因个体差异、镶嵌高度不一致有 2 倍左右的差距。Voronoi 面
积 / 最近邻距离 / Delaunay 边长这三类方法本质上测的都是"点中心之间的距
离"，而不是"钻石之间真实的物理空隙"——不归一化的话，"钻石个体偏小但排
列整齐"的区域和"钻石个体偏大导致中心距变大"的区域会被同一套阈值误判。

**做法**：每颗钻石的检测框算一个等效半径 `r = sqrt(w*h / π)`（把矩形框近似
成等面积的圆），然后：
- 距离类指标（最近邻、Delaunay边）：`gap = 中心距 - (r_i + r_j)`，得到"边
  到边"的真实空隙，而不是中心距。
- 面积类指标（Voronoi）：`normalized_area = 该点的Voronoi胞元面积 / 该点自
  身检测框面积`，剔除"大钻石天然占更大胞元"这个混淆因素。

每个算法都**同时输出 raw（原始中心坐标版）和 normalized（尺寸归一化版）**
两个数值，不是二选一。

**已知近似误差**：钻石实际形状不是圆，用 `w*h/π` 换算等效半径只是一个近
似。如果实测发现归一化后 CV 反而更不稳定，可以尝试换成 `(w+h)/4`（近似半
径）或者用检测框对角线做近似，这是一个可以后续调的点，不是架构性决策。

### 2.5 算法范围

检测结果是"点 + bbox"，不是分割掩膜，所以原分析笔记里针对二值掩膜的"滑窗
密度图"“距离变换"两类方法本期用不上。最终选定：

| 算法 | 是否默认输出 | 备注 |
|---|---|---|
| Voronoi 胞元面积 CV | ✅ | 裁剪到凸包内 |
| 最近邻距离 CV + Clark-Evans R | ✅ | R 只有 raw 版本，见 3.2 |
| Delaunay 边长 CV | ✅ | 实现比 Voronoi 简单，不用处理无界胞元 |
| 网格密度 CV | ✅ | **替代**原方案里的"等面积环形分箱" |
| Ripley's K / L | ❌（可选接口） | 工程上前几种通常够用，留一个更严谨的候选 |

**"等面积环形分箱"为什么被替换成"网格密度CV"**：环形分箱的前提是知道"圆
盘的真实圆心"，但单张 tile 往往只能看到圆盘的一小块弧形区域，既没有圆心
参照，也无法判断这一小块区域"该在哪个半径环上"——这个方法在单图语境下逻
辑不成立。它原本想抓的问题（"一大片区域整体偏疏/偏密"，区别于点对点局部
间距）在单图尺度上仍然有意义，所以换成不依赖圆心的**等分网格密度 CV**：把
凸包的外接矩形切成 n×n 网格，统计每格密度的 CV。

## 3. 算法原理详解

以下 `N` 表示过滤后参与统计的点数，`hull` 表示凸包多边形。

### 3.1 Voronoi 胞元面积 CV

对所有点做 Voronoi 剖分，每个点得到一个"势力范围"多边形。分布越均匀，各
胞元面积应该越接近。

- 用 scipy 算出的 Voronoi 图里，边界点的胞元是无界的（延伸到无穷远），先
  用"沿垂直平分线方向补一个足够远的顶点"的经典算法把每个胞元补成有界多
  边形，再和凸包做交集裁剪，得到每个点在有效区域内"真实"占据的面积。
- `voronoi_area_cv_raw = std(面积) / mean(面积)`
- `voronoi_area_cv_normalized`：先把每个面积除以该点自身检测框面积
  （`π·r²`，等价于 `w·h`），再算 CV。
- **解读**：CV 越接近 0 越均匀；CV 越大说明局部疏密差异越明显。
- **最小样本量**：< 4 个点无法形成有意义的有界剖分，返回 `None`。

### 3.2 最近邻距离 CV + Clark-Evans R

对每个点找最近邻，统计距离分布。

- `nn_distance_cv_raw = std(最近邻距离) / mean(最近邻距离)`
- `nn_distance_cv_normalized`：先把距离换算成 `gap = dist - (r_i + r_j)`
  （边到边间隙），再算 CV。**注意**：拥挤/外接圆重叠时 gap 可能是负数，如
  果 gap 数组均值本身是负的，算出来的 CV 会带负号——这不是 bug，只是提醒
  这类情况下不要直接拿这个 CV 的绝对值跟别的场景比大小，应该看
  `return_details` 里的原始 gap 数组分布。
- **Clark-Evans R**（经典点模式统计量，1954年提出）：
  ```
  R = mean(观测最近邻距离) / E[CSR下的期望最近邻距离]
  E[CSR] = 1 / (2·sqrt(密度))，密度 = N / hull面积
  ```
  - `R ≈ 1`：接近完全随机分布(CSR)
  - `R > 1`：比随机分布更规则/均匀（理论上完美六边形排列时最大约等于
    2.1491，无穷大平面渐近值）
  - `R < 1`：比随机分布更聚集
  - 只对 raw 中心距离计算，因为归一化后已经不是经典 CSR 假设下的统计量了。
- **已知的有限样本偏置**：凸包面积作为"采样窗口"本身会比真实的随机采样面
  积偏小（凸包顶点是极值点，天然收缩），这会让密度估计偏高、期望距离偏
  低，导致 R 系统性偏大。自检脚本里"完全随机分布"场景算出来的 R 是
  1.25 而不是理论上更接近 1 的值，就是这个原因；同理"完美六边形"场景算
  出来的 R（2.38）也超过了 2.1491 的无穷大理论上限。这是有限样本 + 凸包边
  界法的通病，不代表算法实现有错，但意味着 R 的绝对数值不能直接套用文献
  里的理论分界点，需要结合你自己的标注数据重新定阈值。
- **最小样本量**：默认 `min_points_nn = 5`。

### 3.3 Delaunay 边长 CV

Voronoi 的对偶图。对点集做 Delaunay 三角剖分，取所有边的长度分布。

- 不用像 Voronoi 那样处理无界胞元，实现更简单，数值上通常和 Voronoi CV 高
  度相关，可以当作一个交叉验证指标。
- raw / normalized（gap-based）算法与 3.2 一致。
- **最小样本量**：默认 `min_points_delaunay = 5`；点集共线时 Delaunay 会退
  化报错，脚本会捕获并返回 `None`。

### 3.4 网格密度 CV（替代方案）

把凸包的外接矩形切成 `n × n` 网格（`n` 根据点数自适应：目标让每格平均包含
`grid_target_points_per_cell`≈8 个点，`n = round(sqrt(N/8))`，并夹在
`[grid_n_min, grid_n_max] = [2, 6]` 之间），每格用"该格与凸包的交集面积"做
分母算密度（而不是格子的名义面积），过滤掉被凸包切得太碎的格子
（有效面积占比 < `grid_min_valid_area_ratio`=0.15 的格子不参与统计），再算
这些格子密度的 CV。

- **解读**：CV 越大说明存在"整体一半密一半疏"这类大尺度不均匀，这跟
  Voronoi/最近邻抓的"点对点局部间距"是互补的两类信号——两类都低才算真正
  意义上的均匀。
- **最小样本量**：默认 `min_points_grid = 4`。
- 自适应网格数目前是经验公式，拿到真实数据分布后可能需要重新标定
  `grid_target_points_per_cell` 这个目标值。

### 3.5 Ripley's K / L 函数（可选，默认不启用）

多尺度检验：在不同半径 `r` 下比较观测点对数量与 CSR 理论期望值。脚本里的
实现**没有做边界校正**（标准 Ripley's K 需要针对边界附近的点做校正，否则
边界点的邻居会被系统性低估），所以只是留一个接口，默认不进主输出，也不建
议直接拿它的数值定阈值——真要用，需要先补上边界校正。

## 4. 脚本实现说明

### 4.1 模块结构

```
diamond_uniformity.py
├── UniformityConfig          配置项（见4.2）
├── 数据读取 + 过滤
│   ├── load_detections()         读取单个 tile 的 JSON
│   ├── filter_detections()       置信度 + 类别过滤
│   └── load_and_filter()         上面两步的组合
├── 通用工具
│   ├── _cv()                     变异系数
│   ├── _convex_hull_polygon()    凸包（shapely Polygon）
│   └── _extract_points_and_sizes()  中心坐标 + 等效半径
├── 四个核心算法
│   ├── voronoi_area_cv()         + _finite_voronoi_regions() 辅助函数
│   ├── nearest_neighbor_stats()
│   ├── delaunay_edge_cv()
│   └── grid_density_cv()
├── ripley_l_function()           可选，默认不调用
├── compute_uniformity_scores()   主入口，整合以上所有算法
└── 自检 demo（_make_hex_grid / _make_random / _make_clustered_with_hole /
    _self_test）  合成三种典型点分布，验证指标方向是否符合直觉
```

### 4.2 配置项（`UniformityConfig`）

| 字段 | 默认值 | 说明 |
|---|---|---|
| `conf_threshold` | 0.25 | 检测置信度过滤阈值 |
| `allowed_classes` | {棱边朝上,点朝上,面朝上} | 参与空间统计的类别白名单 |
| `min_points_voronoi` | 4 | Voronoi 最小样本量 |
| `min_points_nn` | 5 | 最近邻/CE 最小样本量 |
| `min_points_delaunay` | 5 | Delaunay 最小样本量 |
| `min_points_grid` | 4 | 网格密度法最小样本量 |
| `grid_target_points_per_cell` | 8.0 | 网格自适应目标：每格期望点数 |
| `grid_n_min` / `grid_n_max` | 2 / 6 | 网格数上下限 |
| `grid_min_valid_area_ratio` | 0.15 | 格子有效面积占比阈值，低于此不参与统计 |
| `run_ripley` | False | 是否计算 Ripley's L（默认关闭） |

这些数值目前都是工程经验值，**不是**标定过的阈值——真正的"多少算均匀"判
断阈值完全在这个脚本的职责范围之外，由业务标定流程决定（见第6节）。

### 4.3 输出字段

```jsonc
{
  "n_points": 27,                          // 过滤后参与统计的点数
  "boundary_method": "convex_hull",
  "hull_area": 2028889.44,
  "voronoi_area_cv_raw": 0.6971,
  "voronoi_area_cv_normalized": 0.6649,
  "nn_distance_cv_raw": 0.6606,
  "nn_distance_cv_normalized": 3.2030,     // 注意可能为负，见3.2
  "clark_evans_R": 1.2396,
  "delaunay_edge_cv_raw": 0.6048,
  "delaunay_edge_cv_normalized": 0.9329,
  "grid_density_cv": 0.2428,
  "grid_n": 2,
  "insufficient_data": {                   // 各算法是否因样本不足返回了None
    "voronoi": false, "nn": false, "delaunay": false, "grid": false
  }
  // run_ripley=True 时还会有 "ripley_L" / "ripley_radii"
  // return_details=True 时还会有 "details": {points, radii,
  //   voronoi_cell_areas, nn_distances, nn_gaps,
  //   delaunay_edge_lengths, grid_cell_densities}
}
```

`n_points < 3` 时（比如所有检测都被过滤掉，或者原始检测数就很少），所有算
法字段直接返回 `None`，`insufficient_data` 全部标 `true`，不会尝试硬算。

### 4.4 使用示例

```python
from diamond_uniformity import load_and_filter, compute_uniformity_scores, UniformityConfig

config = UniformityConfig()  # 需要时可以覆盖任意字段，比如 UniformityConfig(conf_threshold=0.3)
points = load_and_filter("9.json", config)
scores = compute_uniformity_scores(points, config)

# 需要中间数组做可视化/直方图时：
scores_detail = compute_uniformity_scores(points, config, return_details=True)
voronoi_areas = scores_detail["details"]["voronoi_cell_areas"]
```

命令行：在 `python_core` 下执行 `python diamond_uniformity.py <json>` 打印分数；不带参数跑自检 demo。

## 5. 已知局限一览

汇总一下前面分散提到的局限，方便后续做二期规划或者出问题时排查：

1. **凸包边界对贴边漏检"失明"**（2.1、2.3）——单图分析架构的固有代价，
   需要整盘坐标合并 + 真实圆盘边界之后才能解决。
2. **Clark-Evans R 存在有限样本 + 凸包边界带来的系统性偏置**（3.2）——数
   值会系统性偏离经典理论值（比如超过六边形排列的理论上限2.1491），不能
   直接套文献阈值，必须结合自己的标注数据重新定界。
3. **gap-based（normalized）CV 在均值跨零时物理意义不稳定**（3.2）——严
   重拥挤场景下可能出现负值，需要看原始分布而不是单看CV数值。
4. **等效半径按 bbox 面积换算成圆是近似**（2.4）——钻石实际形状不是圆，
   如果归一化效果不理想可以换算法。
5. **网格密度法的自适应网格数是经验公式**（3.4）——`grid_target_points_
   per_cell=8` 没有理论依据，需要拿真实数据调。
6. **Ripley's K/L 没做边界校正**（3.5）——只是留个接口，不建议直接用于定
   阈值。
7. **各算法之间可能高度相关**（比如 Voronoi CV 和 Delaunay CV，因为互为对
   偶图）——业务标定阈值时，如果发现某几个算法的判定几乎总是一致，可以
   考虑后续只保留代表性的几个，减少维护成本。

## 6. 后续模块开发规划

### 6.1 与 WPF 主项目的关系

均匀度**已接入**本仓库 WPF：实现为 `python_core/diamond_uniformity.py`，界面为「均匀度分析」页，并在「钻石检测分类」完整模式可选联动。本文仍作为算法含义与边界条件的说明；工程入口与落盘约定见 [应用功能与算法说明.md](应用功能与算法说明.md) 与 [CONTRACTS.md](CONTRACTS.md)。本期**不**要求用 C# 重写该算法。

### 6.2 业务标定流程建议

1. 先用这个脚本跑一批（建议覆盖不同疏密程度、包括正常/边缘/明显缺陷 tile
   的）历史检测结果，拿到每张图的一组分数。
2. 业务/QC 部门对同一批图人工标注"均匀/不均匀"（可以先是二分类，如果后
   续需要更细粒度可以扩展成"轻微/中等/严重不均匀"）。
3. 对每个算法字段，把"均匀"和"不均匀"两组样本的分数分布画出来（箱线
   图/直方图），看两组是否有清晰的分界，**根据实际分布**选阈值，而不是凭
   经验直接定一个数字——这是当初设计时反复强调的一点，也是这个脚本刻意
   不掺和"下判断"这部分逻辑的原因。
4. 关注 `insufficient_data` 标记为 true 的样本：这些是数据量不足、不该进
   入阈值标定的噪声样本，标注时也建议单独标记出来，不要和"真的均匀"混在
   一起统计。
5. 如果几个算法字段的判定高度一致（相关性很高），可以考虑只保留 1-2 个代
   表性指标进正式流程，其余作为辅助参考——降低后续维护和解释成本。

### 6.3 二期：整盘坐标合并之后要做的事

如果后续实现了 tile → 整盘全局坐标的拼接（需要 tile 网格行列映射规则 +
步长/重叠信息 + 圆盘圆心半径的标定值）：

- 边界方法应该从"凸包"换成"真实圆盘边界"，重新评估一遍——很可能会发现
  一批当前凸包法漏判的贴边缺陷（见第5节第1条）。
- 原方案里的"等面积环形分箱"可以真正启用（当前用"网格密度CV"是单图场
  景下的替代方案，不是永久方案）。
- Clark-Evans R 的系统性偏置（第5节第2条）在整盘尺度、点数更多的情况下应
  该会明显减小，值得重新核对一遍是否还需要额外校正。
- 需要重新考虑：是按整盘出一个总分，还是仍然保留分区域（比如按象限/环
  带）的细粒度分数——这取决于业务部门想要多细的定位能力。

### 6.4 决策记录（Decision Log）

| # | 决策点 | 最终选择 |
|---|---|---|
| 1 | 分析粒度 | 单图(tile)级别，不做整盘合并 |
| 2 | 现有pipeline的跨tile处理 | 只是重复检测去重，不含全局坐标转换（因此本期不依赖它）|
| 3 | 尺寸归一化 | raw + normalized 两版都算，等效半径法 |
| 4 | 算法范围 | Voronoi CV / 最近邻CV+CE / Delaunay CV / 网格密度CV（替代环形分箱）；Ripley's K可选 |
| 5 | 过滤规则 | 置信度阈值(默认0.25) + 类别白名单(棱边朝上/点朝上/面朝上) |
| 6 | 输出粒度 | 简洁dict主输出 + return_details选项 |
| 7 | 有效分析区域 | 凸包（已知局限：对贴边漏检"失明"）|
| 8 | 小样本保护 | 各算法独立min_points阈值，不足时返回None+标记 |
| 9 | 与WPF项目的集成方式 | 仅作原型/参考实现，不做CLI/子进程封装 |
