# 钻石缺陷分类系统 — WPF 打包与机台部署

本文对应原 PyQt 版「打包部署说明」，交付物改为 **WPF 宿主 + python_core +（可选）Python 运行时**。

| 项 | 说明 |
|----|------|
| 正式组装入口 | `scripts/build_deploy_wpf.ps1` |
| 仅发布宿主 | `scripts/publish_wpf.ps1` |
| 验收 | `scripts/verify_wpf.ps1` 或包内 `验收_verify.bat` |
| 输出目录 | `dist/缺陷分类系统/` |

---

## 1. 两种运行模式

| 模式 | 触发 | 分类 | 再训练 |
|------|------|------|--------|
| 开发版 | 默认 | PyTorch 优先 | 可解锁后训练 |
| 机台版 | `DEFECTS_DEPLOY=1` 或 `启动缺陷分类系统.bat` | ONNX Runtime | 只读 |

---

## 2. 打包前准备

1. Conda 环境 **`cv-yolo`** 可跑通推理 / SAHI（与开发一致）。
2. `checkpoints/` 至少含：
   - `model.onnx`（及 `.data` 若有）
   - `class_map.json` / `train_config.json`
   - （**不再打包** `class_thresholds.json`；应用侧已忽略逐类阈值）
3. YOLO 权重：`app_config.json` 的 `yolo_path`，或仓库内 `detect_weights/best.pt`。
4. 已安装 .NET 8 SDK，可 `dotnet publish`。

验收模型（开发目录）：

```powershell
cd D:\Develop\diamond_detect_wpf
$env:DIAMOND_PYTHON_HOME = "D:\Software\MiniAnaconda\envs\cv-yolo"
.\scripts\verify_wpf.ps1
```

## 3. 组装机台包

### 3.1 完整包（含 Python 运行时，体积大）

```powershell
conda activate cv-yolo
cd D:\Develop\diamond_detect_wpf
.\scripts\build_deploy_wpf.ps1 -PythonHome "D:\Software\MiniAnaconda\envs\cv-yolo"
```

会：

1. `dotnet publish` 自包含 WPF → `dist\_wpf_publish`
2. 组装到 `dist\缺陷分类系统\`：exe、`python_core`、`checkpoints`、`detect_weights`、`python_runtime`（torch + CUDA 运行时 + ultralytics）、机台 `app_config.json`、启动/验收 bat

若默认目录被正在运行的程序占用，可指定输出目录：

```powershell
.\scripts\build_deploy_wpf.ps1 -PythonHome "D:\Software\MiniAnaconda\envs\cv-yolo" -OutDir "D:\Develop\diamond_detect_wpf\dist\缺陷分类系统_完整版"
```

机台只需已安装 **NVIDIA 显卡驱动**（不必再装 CUDA Toolkit）。体积约 7 GB。

### 3.2 瘦包（不复制 Python 运行时）

机台已安装相同 Conda 环境时：

```powershell
.\scripts\build_deploy_wpf.ps1 -SkipPythonRuntime
```

机台启动前设置：

```bat
set DIAMOND_PYTHON_HOME=D:\path\to\envs\cv-yolo
set DEFECTS_DEPLOY=1
```

### 3.3 仅重新发布 UI

```powershell
.\scripts\publish_wpf.ps1
.\scripts\build_deploy_wpf.ps1 -SkipPublish -PythonHome "..."
```

## 4. 交付目录结构

```
缺陷分类系统/
├── DiamondDetect.exe
├── 启动缺陷分类系统.bat      ← 设 DEFECTS_DEPLOY=1 并指向 python_runtime
├── 验收_verify.bat
├── README_机台.txt
├── app_config.json           ← 相对路径机台配置
├── checkpoints/
├── detect_weights/best.pt
├── python_core/
└── python_runtime/           ← 可选；完整包时存在
```

**必须整包复制**到机台。体积主要来自 `python_runtime`（torch / CUDA / ultralytics），量级可与原 PyInstaller 包相近（约数 GB）。

## 5. 机台部署与运维

### 5.1 首次

1. 整包拷到机台目录（勿只拷 exe）。
2. 运行 `验收_verify.bat`，期望输出含 `模型加载成功`、`3 类别` 与 `device: cuda`（或 CPU 警告但仍可运行）。
3. 双击 `启动缺陷分类系统.bat`。

### 5.2 仅更新分类模型

覆盖机台 `checkpoints/` 中 `model.onnx`（及 `.data`）、`class_map.json`、`train_config.json`，重启即可（启动自动加载）。无需、亦不应依赖 `class_thresholds.json`。

### 5.3 仅更新 YOLO

覆盖 `detect_weights/best.pt`。

### 5.4 主动学习

机台 `corrections/` → 拷回开发机 →  
`python train.py --finetune --extra_data_dirs corrections` →  
更新机台 `checkpoints/`。

### 5.5 设置页

默认管理员锁定。改 SAHI/YOLO 需解锁。日常检测不必进设置。

## 6. 与旧 PyQt 包关系

| | 旧包 | WPF 包 |
|--|------|--------|
| UI | PyQt5 / PyInstaller | .NET 8 WPF |
| 算法 | 同左 | **同一套** `python_core` |
| 验收变量 | `DEFECTS_VERIFY=1` | 同 + `--verify` |
| 机台开关 | `DEFECTS_DEPLOY=1` | 同 |

过渡期两包可并行，共用同一套 `checkpoints` 对比结果。

## 7. 常见问题

**Q: 启动提示找不到 Python**  
A: 确认 `python_runtime` 存在，或设置 `DIAMOND_PYTHON_HOME` / `DIAMOND_PYTHON_DLL`。

**Q: 分类引擎未加载**  
A: 检查 exe 同级 `checkpoints/model.onnx` 与 `app_config.json`。

**Q: SAHI / YOLO 失败**  
A: 检查 `detect_weights/best.pt`；设备设为 `auto`；确认运行时含 ultralytics/torch。

**Q: 验收显示几类？**  
A: 现行应用层为 **3 类别**。若仍见 5 类，说明包内 `python_core` 过旧，请重新组装机台包。

**Q: 误删钻石检测输出里的 summary.csv？**  
A: 将 `rebuild_summary_from_stats.exe`（由 `scripts/build_rebuild_summary_exe.bat` 生成）放到结果根目录双击，根据一层子目录的 `statistics.json` 重建。源码：`scripts/rebuild_summary_from_stats.py`。
