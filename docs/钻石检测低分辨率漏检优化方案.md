# 钻石大图检测：低分辨率漏检分析与后续优化路线

> 文档版本：2026-09-01  
> 适用系统：DiamondDetect WPF · SAHI + YOLOv8 检测 + ONNX 三分类  
> 背景：5120×5120 原图检测基本正确；压缩/下采样至约 2560 后出现明显漏检，小目标更严重。

---

## 1. 问题复述与对比基准

| 场景 | 输入 | 模式 | 现象 |
|------|------|------|------|
| 产线基准 | 5120×5120 原图 | 检测+分类 或 仅检测 | **召回基本正确** |
| 加速试验 | 预压缩图（如 `33_compressed.jpg`）或 App 内下采样至最长边 2560 | 仅检测定位 + 可视化 | **漏检增多**，体积小的钻石更明显；偶有大钻漏检 |

对比方式：同一场景、同一参数配置，仅改变输入分辨率。

---

## 2. 根因分析（是否后处理导致？）

### 2.1 结论摘要

**主因不是后处理逻辑错误，而是「检测尺度失配 + 模型分布偏移」。**  
后处理（面积 / 边缘 / IoS / 长宽比）在全分辨率下与模型配套，在低分辨率上会**放大**漏检，但通常不是第一原因。

### 2.2 因果链

```
输入分辨率降低（5120 → 2560，面积约 1/4）
    ↓
每颗钻石在 SAHI 切片内的像素尺寸约减半（面积约 1/4）
    ↓
YOLO 置信度下降，大量候选在 conf=0.35 之前被丢弃  ← 主漏检
    ↓
侥幸检出的框再经后处理链过滤  ← 次因，小目标更吃亏
```

### 2.3 当前流水线关键参数（全分辨率下调参，低分辨率未联动）

| 参数 | 典型值 | 低分辨率下的影响 |
|------|--------|------------------|
| `sahi_slice_size` | 1280 | 2560 图上切片覆盖变「粗」，单切片内目标更小 |
| `sahi_det_conf` | 0.35 | 弱检测被整批丢弃 |
| `sahi_min_area_ratio` | 0.45 | 相对中位面积过滤；召回已偏低时易误删偏小真值 |
| `sahi_edge_margin_px` | 20（绝对像素） | 在 2560 图上相对边带更宽（约等效原图 40px） |
| `sahi_ios_thresh` | 0.60 | 切片边界重复检测合并时可能误删 |
| 下采样插值 | area（默认） | 缩小图细节模糊，利于速度但不利于小目标 |

### 2.4 为何「大钻也会漏」

与同尺寸已检出框并存时，更指向 **YOLO 召回波动**（纹理、局部对比度、切片边界、压缩伪影），而非单纯的面积后处理（同尺寸框应被同等对待）。

---

## 3. 产线短期策略（已采纳）

1. **机台使用 5120×5120 原图**，不依赖压缩图或下采样做正式检测。  
2. **完整检测+分类模式**继续输出根目录 `summary.csv`（单张、多选文件、文件夹批量均包含；多张时有「批次合计」行）。  
3. 低分辨率路径保留为**研发测速与对照实验**，不作为产线默认。

---

## 4. 优化方向总览

按投入与风险排序：

| 阶段 | 方向 | 目标 | 周期量级 |
|------|------|------|----------|
| P0 | 产线全分辨率 + 推理调优 | 稳定召回 | 已完成/持续 |
| P1 | 配置与诊断 | 量化漏检发生在 YOLO 还是后处理 | 1–3 天 |
| P2 | 工程多尺度适配 | 下采样时联动 `slice_size`、边缘阈值等 | 1–2 周 |
| P3 | 两阶段检测 | 低分辨率粗检 + 原图 ROI 精检 | 2–4 周 |
| P4 | 数据与重训 | 从根本匹配部署尺度 | 4–8 周+ |
| P5 | 换架构（DETR 等） | 仅当 YOLO 路线证伪 | 8 周+ |

## 5. 数据层面

### 5.1 标注与样本

- **保留全分辨率标注为主**；若未来必须跑 2560，应增加 **同场景 2560 下采样/压缩图** 的标注或自动伪标注校对。  
- **小目标过采样**：训练集中对小框样本提高采样权重或复制增强。  
- **难例挖掘**：将压缩图漏检、原图检出的位置裁切入库，人工复核后加入训练集。  
- **压缩退化仿真**：训练时随机 JPEG 质量、轻微模糊、对比度变化，模拟 `*_compressed.jpg` 分布。

### 5.2 评估集

建议固定 **20–50 张** 代表图，每张维护：

- 原图 5120 检出（基准 GT 或高置信 pipeline 输出）  
- 压缩/2560 检出  
- 指标：Recall、Precision、按框面积分桶的 Recall（小/中/大）

### 5.3 诊断脚本（建议）

对同一张图输出各阶段框数：

`YOLO raw → NMS → IoS → 面积 → 长宽比 → 边缘 → 最终`

用于回答：「漏检中有多少比例发生在后处理之前」。

## 6. 模型重训练（YOLOv8 / Ultralytics）

### 6.1 是否重训

| 部署策略 | 是否建议重训 |
|----------|--------------|
| 长期仅 5120 原图 | **可选**（以难例迭代为主） |
| 长期 2560 或压缩图 | **强烈建议**多尺度重训 |

### 6.2 推荐训练策略

1. **基线**：在现有 `best.pt` 上 **微调**（freeze 少量层 + 小学习率），避免灾难性遗忘。  
2. **多尺度输入**：`imgsz` 混合 1280 / 1920 / 2560；或原图训练 + 随机 0.5× 缩放增强。  
3. **小目标增强**：Mosaic、Copy-Paste（若标注支持）、适当提高 `box` loss 权重。  
4. **验证**：必须在 **2560 压缩图验证集** 上选 best，而非仅在 5120 上选。  
5. **导出**：仍导出 `.pt` 供 SAHI；可选 TensorRT 加速全分辨率推理。

### 6.3 与 SAHI 的配合

- 训练时 `imgsz` 与部署 `slice_size` 宜接近（如 1280 切片 → 训练常用 1280/640 多尺度）。  
- 若部署固定 2560 全图，可考虑 **`slice_size=640`**（等效 5120+1280 的目标尺度），需在验证集上对比。

---

## 7. 多尺度工程适配（不改权重）

在 **必须下采样** 时，参数应随缩放比联动，而非只改图像：

| 全分辨率基准 | 缩放 0.5×（2560）建议起点 |
|--------------|---------------------------|
| `slice_size=1280` | `slice_size=640` |
| `edge_margin_px=20` | `edge_margin_px=10` |
| `det_conf=0.35` | `0.22–0.28`（需验证） |
| `min_area_ratio=0.45` | `0.25–0.35` 或暂时关闭做 AB 测试 |
| `overlap=0.2` | `0.25–0.3`（略增重叠） |

**实现建议**：在 `SahiDetectOnlyPipeline` / 下采样分支内，根据 `scale = max_side / original_max_side` 自动缩放 `slice_size` 与 `edge_margin_px`，并写入日志供追溯。

## 8. 模型架构选型（YOLO 之外）

### 8.1 对比维度

工业大图密集小目标检测需同时看：**小目标召回、推理速度、切片兼容性、工程成熟度**。

| 架构 | 优势 | 劣势 | 与本项目契合度 |
|------|------|------|----------------|
| **YOLOv8/v11 + SAHI** | 成熟、快、已集成 | 低分辨率需重训或联动参数 | ★★★★★ 当前基线 |
| **RT-DETR / DEIM** | 端到端、NMS 可选 | 大图仍需切片；训练成本高 | ★★★ 可试点 |
| **DETR / DINO-DETR** | 全局建模、少 NMS | 慢、显存大、5120 不现实整图推理 | ★★ 研究向 |
| **Grounding DINO** | 开放词汇 | 需文本 prompt；工业类固定 | ★ 不推荐作主检测器 |
| **SAM / SAM2** | 分割强 | 非检测器；需额外分类 | ★ 可作辅助标注 |

### 8.2 建议

- **产线主路径**：继续 **YOLO + SAHI**，通过全分辨率 + TensorRT + batch 提速。  
- **若 YOLO 在 2560 重训后仍不达标**：试点 **RT-DETR-L** 等与 SAHI 结合，在小验证集上与 YOLO 对比 Recall@固定 FP。  
- **不建议** 用 DINO 类 Transformer 直接替换整图检测（5120 显存与延迟不现实），除非只做 ROI 精检二级模型。

## 9. 两阶段检测（速度 vs 精度平衡）

适用于「希望比全图 5120 快、又不愿接受纯 2560 漏检」：

```
阶段 A：2560（或压缩图）粗检 → 得到候选框（可放低 conf）
阶段 B：将框映射到 5120 原图坐标，扩展 margin，仅在 ROI 上跑 1280 切片精检
阶段 C：（可选）融合 A/B 框，再分类
```

- **优点**：全图推理面积小；小目标在 ROI 内尺度恢复。  
- **缺点**：工程复杂度上升；阶段 A 漏检会导致阶段 B 无法召回（需 A 阶段高召回、允许略多 FP）。

---

## 10. 后处理调参指南（AB 实验）

在固定压缩图上，建议按序单变量测试：

1. 关闭 `edge_filter` → 若 Recall 明显上升，则联动缩小 `edge_margin` 或仅低分辨率关闭。  
2. `det_conf`：0.35 → 0.30 → 0.25，画 Recall-FP 曲线。  
3. `min_area_ratio`：0.45 → 0.30 → 关闭。  
4. `ios_thresh`：0.60 → 0.70（减少误删）。  
5. `slice_size`：1280 → 960 → 640。

**注意**：后处理只能挽回「已被 YOLO 检出」的框，无法恢复未检出的目标。

## 11. 不降分辨率的提速手段

| 手段 | 说明 |
|------|------|
| GPU + `sahi_device=auto/cuda` | 基线 |
| 增大 `sahi_batch_size` | 在显存允许下提高切片 batch |
| TensorRT / ONNX 导出 YOLO | 需验证与 ultralytics 版本兼容 |
| 固定 `slice_size` 与 overlap 的网格预计算 | 微优化 |
| 分类与检测并行流水线 | 架构级，改动大 |

## 13. 风险与决策点

| 风险 | 缓解 |
|------|------|
| 压缩图重训后 5120 略降 | 多尺度混合训练；双 checkpoint 按输入分流 |
| 两阶段 A 漏检传递 | A 阶段高召回配置 + 原图滑动窗口兜底 |
| 换 DETR 周期过长 | 仅作验证集对比，不阻断 YOLO 产线 |
| 后处理调参过松导致 FP 激增 | 以产线可接受 FP 上限约束 Recall 优化 |

